## 成立性の確認（Probe、2026-11-28、合格）

1. **`@mozilla/readability` 0.6.0 は content script の中で動く（合格）**。基準ページ: 見出し 8・p 22・li 21・pre 1・code 4・リンク 23。react.dev/learn: 見出し 13・p 193・pre 24・code 107・img 8。見出しのアンカー（react.dev の見出し横のリンク）も残った。どちらのページにも表はなかった。npm で 0.6.0・Apache-2.0・展開後 154,574 バイトを確認。

## 要件・決定事項

設計書の「操作」「リーダー画面」「翻訳との関係」「原文の吹き出し」をそのまま要件とする。加えて、設計書が「後で決めてよい」とした事項と、設計書が触れていない細部を次のとおり決める。

### リーダー表示

- **開き方**: 拡張の右クリックメニュー 1 項目「リーダー表示」を、ツールバーのボタン（`contexts: ["action"]`）とページ（`["page"]`）に出す。キーボードショートカットは `commands` で `Alt+Shift+R`（Mac では Option+Shift+R）を既定にする。利用者は `chrome://extensions/shortcuts` で変えられる（他の拡張とぶつかると Chrome が割り当てないことがある。それは README に書く）。
- メニューとショートカットは、リーダーが開いていれば閉じる（切り替え）。ツールバーのボタンは今のまま翻訳モードの切り替え。
- **Esc で閉じる**（Plan Review で利用者が追加、2026-11-28）: リーダーを開いている間に Esc を押すと、✕ と同じく閉じる。リーダーの中で文字を選択中でも閉じる。リーダーを開いている間の Esc はリーダーが先に受け取り、ページには渡さない（ページ側のダイアログなどが同時に閉じない）。設計書の「操作」にはない追加なので、設計書にも書き足す。
- **抜き出し**: 開いた時点の `document` の複製に Readability をかけ、`parse()` が `null`、または本文が空なら開かない。代わりに、既存の接続エラーと同じ見た目の小さな通知で「このページはリーダー表示にできません」と出し、数秒で消す。
- **画面**: 今のタブの上に全画面で重ねる（Shadow DOM。ページの CSS は入らない）。中身は開いた時点の写しで、後のページの変化は反映しない。重ねた画面の中だけがスクロールし、ページはスクロールしない（`overscroll-behavior: contain` など）。閉じると、元のページは開く前の位置のまま。
- **上部のバー**: 翻訳 ON/OFF、背景（黒・セピア・白）、ゴシック/明朝、文字 −/+、行幅 −/+、✕ 閉じる。
- **見た目の値**:
  - 背景（背景色 / 文字色 / コードの枠の背景色）: 黒 `#1e1e1e` / `#d4d4d4` / `#2a2a2a`、セピア `#f4ecd8` / `#5b4636` / `#ebe1c9`、白 `#ffffff` / `#1f1f1f` / `#f4f4f4`。リンクの色は背景ごとに読める色を選ぶ。
  - ゴシック: `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Yu Gothic", Meiryo, sans-serif`。明朝: `"Hiragino Mincho ProN", "Noto Serif JP", "Yu Mincho", serif`。コード: `ui-monospace, "SF Mono", Menlo, Consolas, monospace`（固定）。
  - 文字の大きさ: 14・16・18・20・22・24・28 px の 7 段階。
  - 行幅（本文の最大幅）: 30・35・40・45・50・60 em の 6 段階（1em ≒ 全角 1 字）。
  - 既定: **黒**、ゴシック、18px、40em（改訂で白から黒に変更）。
- **見た目の保存**: 背景・フォント・文字の大きさ・行幅を `chrome.storage.local` に保存し、次に開いたときに使う。設定画面には置かない。既存の `Settings` とは別のキー（例 `reader`）にしてよい（形は実装で決める）。
- **リンク**: リーダーの中のリンクを押したら、リーダーを閉じて、元のページ（同じタブ）でそのリンク先へ移動する（Readability は相対 URL を絶対 URL にする）。ページ内アンカー（`#…`）も同じく、閉じてから元のページで移動する。
- **コードブロック**: 等幅フォントで背景色に合う枠。翻訳しない（既存の抽出規則で `pre` は送らない）。行ごとの要素で組まれたコードブロック（react.dev など）も、元のページで見えるとおりの行と字下げで、行の間を空けずに表示する。そのため、Readability にかける前に、複製の `pre` の中身を元のページの `pre` の見たままの文字だけの `code` に置き換える（Probe 3。色付けはもともと対象外なので `span` は捨ててよい）。改行の整え方の細部（空行の扱いなど）は実装で決める。
- **ページを離れるとき**: bfcache に入るとき（`pagehide` の `persisted`）は、翻訳モードと同じくリーダーも閉じる。

### 翻訳との関係

- 翻訳モードはタブに 1 つ。バーの翻訳 ON/OFF、ツールバーのボタンのどちらでも同じモードを切り替え、バッジ（`ON`・空・`ERR`）も同じ。
- 翻訳モードがオンのままリーダーを開くと、元のページ向けの新しい送信を止め（送信済みの応答はどう扱ってもよい）、リーダーの中だけを訳す。元のページの訳文はそのまま残す。
- リーダーを閉じたとき翻訳モードがオンなら、元のページの翻訳を再開する。すでに訳した段落は訳し直さず、未訳の段落と、止めていた間にページが足した・変えた段落を訳す。リーダーの中の訳は捨てる（開き直すと訳し直す）。
- 翻訳モードがオフでリーダーを開くと原文のまま表示し、バーかボタンでオンにするとリーダーの中を訳す。リーダーを開いている間にオフにすると、リーダーの中を原文に戻す。
- 表示方法（置き換え・対訳）は設定に従う。llama-server に接続できないときの通知は、リーダーの上に見える。

### 原文の吹き出し

- 置き換えた段落に `title` 属性を付けるのをやめ、自前の吹き出しにする（元のページとリーダーの両方）。対訳表示では原文が見えているので出さない。
- 置き換えた段落にマウスを乗せて 0.5 秒たつと、原文の吹き出しを段落のすぐ下に出す。下に入りきらず、上に入るなら上に出す（どちらにも入らなければ下）。
- 吹き出しの文字の大きさは段落の計算済みの `font-size`、幅は段落の幅。中身は Shadow DOM に描き、原文の文字を選んでコピーできる（マウスを吹き出しへ動かしても消えない。段落と吹き出しの両方から離れると消える）。
- **吹き出しの見た目**（改訂で決め直し）: 本文の背景と区別できる色にする。角丸・影（`0 4px 16px rgba(0,0,0,.25)`）・余白・行の高さは #13 の実装のまま。

  | 場所 | 背景色 | 枠（1px） | 文字色 | フォント |
  | --- | --- | --- | --- | --- |
  | 元のページ（どのページでも固定） | `#fff6cc` | `#b8921a` | `#1f1f1f` | `system-ui, sans-serif`（#13 のまま） |
  | リーダー 白 | `#fff6cc` | `#b8921a` | `#1f1f1f` | リーダーのゴシック/明朝 |
  | リーダー セピア | `#fff6cc` | `#b8921a` | `#3e2f22` | リーダーのゴシック/明朝 |
  | リーダー 黒 | `#2d2d2d` | `#5a5a5a` | `#e6e6e6` | リーダーのゴシック/明朝 |

  リーダーを開いている間に背景・フォントを変えたら、次に出す吹き出しから新しい見た目にする（出ている吹き出しをその場で変える必要はない）。
- 吹き出しは拡張が差し込む要素として扱い、`MutationObserver` の対象外にする（既存の目印の仕組みを使う）。オフ・閉じるときに消える。
- 訳せなかった段落の ⚠ の目印の `title`（理由の表示）は今のまま。

## 制約・対象外

- 対象外（設計書のとおり）: 開いた後のページの変化への追従、コードブロックの色付け、Web フォントの読み込みとフォントの一覧からの選択、タッチ操作やキーボードでの原文表示。
- 対象外: 設定画面への見た目の項目の追加、Chrome のリーディング モードとの連携。
- 通信先はローカルの llama-server だけ（`host_permissions` は変えない）。依存は `@mozilla/readability` 0.6.0（`dependencies`、版を固定）だけ増やす。権限は `contextMenus` だけ増やす（`commands` は権限が要らない。右クリックメニューとショートカットでも `activeTab` が与えられる）。
- 正式チェックは `pnpm run check`。
- 作業開始時点で `docs/designs/browser-translator.md`（変更）と `docs/designs/reader-mode.md`（新規）が未コミット。保持し、変更・破棄しない。コミットに含める時期は Implementation で利用者に確認する。
- 過去の Approved Plan（`docs/plans/*.md`）は書き換えない。

## 実装方針

既存の構成（1 つの content script がタブの状態を持ち、service worker が注入する）を保つ。

- `src/manifest.json`: `permissions` に `contextMenus`、`commands` にリーダーの切り替え（`suggested_key` は `Alt+Shift+R`）。
- `src/background.ts`: `chrome.runtime.onInstalled` で右クリックメニューを作る。メニューの `onClicked` とショートカットの `onCommand` で「リーダーの切り替え」を、ボタンで「翻訳モードの切り替え」を content script に伝える（注入の前に命令を渡す方法は実装で決める）。検証 helper が呼べるよう、リーダーの切り替えの関数を既存の `Object.assign(globalThis, …)` に加える。
- `src/content.ts`: 翻訳処理を「対象の root（`document.body` か、リーダーの `article`）」で動かせるようにする（段落の収集・`MutationObserver` の対象。Probe では対象を替えるだけで動いた）。一時停止（新しい送信を止め、監視を外す）と再開（root を見直し、未訳・変わった段落だけを足す）を足す。吹き出しを使うよう `show()` から `title` の設定・戻しを外す。
- リーダーと吹き出しのコードは、大きくなるなら新しいファイル（例 `src/reader.ts`・`src/bubble.ts`）に分け、`content.ts` から import する（ビルドは content のエントリー 1 つのまま。`scripts/build.ts` は変えない見込み）。
- 吹き出しの位置の決め方（下に入るか・上に入るか）は、DOM に触れない小さな関数にしてテストする。
- 文書:
  - `README.md`: 使い方にリーダー表示（開き方・バー・Esc で閉じる・見た目の保存・ショートカットの変え方）と吹き出しを足し、「置き換え表示ではマウスを乗せると原文が出る」と設定の表示方法の説明を吹き出しに合わせる。「現在の制限」に、リーダーは開いた時点の写しであることと、抜き出せないページでは開かないことを足す。
  - 設計書 `docs/designs/reader-mode.md`: 「未確認・リスク」の上 2 行を Probe の結果で確認済みにし、実装後の確認（アンカー・表・画像、フォント）の結果を書く。「後で決めてよいこと」を決めた値で置き換える。「操作」に Esc で閉じることを足す。`browser-translator.md` は、表示の節がすでに設計書を指しているので、必要な場合だけ直す。
  - 設計書 `docs/designs/reader-mode.md`（改訂）: 「原文の吹き出し」に「本文の背景と区別できる色にする（元のページは固定の薄い黄、リーダーは背景ごと）」とその理由（白いページで白い吹き出しは目立たない）を足し、「後で決めてよいこと」を置き換えるときに吹き出しの色とリーダーの既定（黒）も書く。`README.md` に既定の背景を書くなら黒にする。
  - 検証 Skill（`.pi/skills/verify-project/`）: 「動作確認方法」のとおり更新する。Feature Map の「置き換え翻訳」の注意にある吹き出しの見た目（白地・濃い文字・影）を新しい色に直す。

## 完了条件

1. 右クリックメニュー（ボタン・ページ）とショートカットでリーダーが開き、もう一度で閉じる。抜き出せないページでは開かず、通知が出る。
2. リーダーは今のタブに重なった Shadow DOM で、開いた時点の本文（見出し・段落・コードブロック）を描く。react.dev のコードブロックは、元のページと同じ行と字下げで、行の間を空けずに表示される。バーで背景・フォント・文字の大きさ・行幅が変わり、それが保存されて次回も使われる。✕ と Esc で閉じると元のページが同じ位置に戻る（Esc はページに渡らない）。リンクを押すとリーダーが閉じ、元のページで移動する。
3. 翻訳モードはタブに 1 つ。リーダーを開いている間は、リーダーの中だけが訳され（元のページ向けの新しい送信は 0）、閉じると元のページの翻訳が再開する（訳済みの段落は送らない）。置き換え・対訳の両方で、文中の要素が保たれる。
4. 置き換えた段落に `title` 属性がなく、マウスを乗せると 0.5 秒ほどで原文の吹き出しが段落のすぐ下（入らなければ上）に、段落と同じ文字の大きさ・幅で出て、文字を選んでコピーできる。元のページとリーダーの両方で動く。吹き出しの背景色・枠の色・文字色が「吹き出しの見た目」の表のとおりで、リーダーの中ではフォントがリーダーの設定と同じ。リーダーを初めて開くと背景は黒。
5. `pnpm run check` が成功する。
6. 実装後の確認として、Readability が見出しのアンカー・表・画像を残すかと、ゴシック・明朝のフォントが Mac で当たるかを観測し、結果を設計書と `run.md` に書く。
7. 既存の検証（基準ページの置き換え・対訳、react.dev、設定画面）が、吹き出しに合わせた helper の更新後もすべて true。
8. README・設計書・検証 Skill が実装に合っている。

## 動作確認方法

### 保証する・しない

- 保証する: 完了条件 1〜4 の振る舞い、既存の翻訳（元のページ）が壊れないこと、オフ・閉じるでページの DOM が元に戻ること、通信先が設定の llama-server だけであること。
- 保証しない: Readability がすべてのサイトで本文を正しく取ること（観測して記録するだけ）、Mac 以外のフォント、訳文の品質。
- 完了条件 6 は観測で、結果が悪い（例: 表が落ちる）場合は記録して利用者に報告する。直すことがこの Plan の範囲外の設計変更になるなら、REPLAN_REQUIRED にする。

### 自動テスト（`pnpm run check`）

- 吹き出しの位置の関数: 下に入る → 下、下に入らず上に入る → 上、どちらにも入らない → 下、の 3 ケース程度。
- 既存のテスト（`test/text.test.ts` など）は変わらず通る。
- 追加しない自動化: リーダー・吹き出し・右クリックメニューを jsdom などで動かすテスト、Chrome を使う E2E の CI 化。これらは Readability・Shadow DOM・`IntersectionObserver`・実際の描画に依存し、jsdom では保証にならないため、下の実動作確認で見る。

### TDD

- 採用しない。中心は Chrome の API と描画に依存する UI で、test-first の利点が小さい。吹き出しの位置の関数は小さいので、実装と同時にテストを書けば足りる。

### 実動作確認（検証 Skill `.pi/skills/verify-project/`）
