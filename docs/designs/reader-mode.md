# リーダー表示と原文の吹き出し 基本設計

最終更新: 2026-11-28

全体の設計は [browser-translator.md](browser-translator.md) を参照。

## 目的と期待する結果

英語の技術記事を、広告やサイドバーのない読みやすい画面で、訳しながら読めるようにする。あわせて、マウスを乗せたときに出る原文を読みやすい大きさにする。

次の状態になれば目的を満たす。

- 本文だけが、選んだ背景（黒・セピア・白）、フォント、文字の大きさ、行幅で表示される。
- リーダーの中でも、今と同じ品質で訳せる（文中の要素の保持、表示方法の設定）。
- 原文の吹き出しが、本文と同じくらいの大きさで読め、コピーもできる。

## 範囲

**扱う**
- 今のタブに重ねて表示するリーダー画面と、その中での翻訳
- 原文の吹き出し（元のページとリーダーの両方）

**扱わない**
- 開いた後のページの変化への追従（開き直してもらう）
- コードブロックの色付け
- Web フォントの読み込み、インストール済みフォントの一覧からの選択
- タッチ操作やキーボードでの原文表示

## 操作

- ツールバーのボタンは、今のまま翻訳モードの切り替えに使う。翻訳だけを使う場面が多いため。
- リーダー表示は、右クリックメニュー（ツールバーのボタンとページ）とショートカットキーで開く。
- リーダー画面の上部に細いバーを置く。

```
[翻訳 ON/OFF] [黒|セピア|白] [ゴシック|明朝] [文字 −/+] [行幅 −/+]   [✕ 閉じる]
```

- バーの翻訳 ON/OFF は、ツールバーのボタンと同じ翻訳モードを切り替える（翻訳モードはタブに 1 つ）。
- 背景・フォント・文字の大きさ・行幅はバーで変え、保存して次回も使う。設定画面には置かない。

## リーダー画面

- 今のタブのページの上に、全画面で重ねる。中身は Shadow DOM（ページの CSS が入り込まない、隔離された DOM）に描く。閉じれば元のページの同じ位置に戻る。
- 開いた瞬間に `@mozilla/readability` で本文を抜き出し、その写しを描く。開いた後に元のページが変わっても、リーダーには反映しない。
- 本文を抜き出せないページでは、「このページはリーダー表示にできません」と短く出して開かない。
- リーダー内のリンクを押したら、リーダーを閉じて元のページで移動する。
- コードブロックは、等幅フォントで背景色に合う枠を付けて表示する。翻訳はしない。
- フォントはゴシックと明朝の 2 択。PC に入っているフォントを、OS ごとの並び（例: Hiragino Sans → Noto Sans JP → `sans-serif`）で指定する。コードの等幅フォントは固定にする。
- 行幅を指定しないときは、読みやすい幅（全角 40 字前後）にする。

## 翻訳との関係

- 翻訳には、今の content script の仕組み（段落の抽出、タグ、見えている段落を先に訳す処理）を、リーダーの中身に向けて使う。
- リーダーを開いている間は、リーダーの中だけを訳す。元のページの翻訳は止め、閉じたら再開する。
- 表示方法（置き換え・対訳）は設定に従う。
- リーダーの中身はページのスクリプト（React など）の管理外なので、置き換えが崩れる問題は起きない。

## 原文の吹き出し

- 標準のツールチップ（`title` 属性）をやめる。標準のツールチップは文字の大きさや幅を拡張から変えられず、コピーもできないため。
- 置き換えた段落にマウスを乗せると、少し間（0.5 秒程度）を置いて、段落のすぐ上か下に原文の吹き出しを出す。
  - 文字の大きさは段落の本文と同じにし、幅は段落に合わせる。
  - 中身は Shadow DOM に描き、原文の文字は選んでコピーできるようにする。
- 元のページでもリーダーでも使う。リーダーの中では、背景とフォントに合わせた見た目にする。
- 吹き出しは本文の背景と区別できる色にする。元のページは固定の薄い黄（付箋風。背景 `#fff6cc`・枠 `#b8921a`・文字 `#1f1f1f`）で、OS の明暗やページの背景色では変えない。リーダーの中は背景ごとに決める。白いページで白い吹き出しは目立たなかったため。

## 決定と理由

| 決定 | 理由 |
| --- | --- |
| 本文を抜き出して拡張が描く（Chrome のリーディング モードや、ページへの CSS 追加ではない） | 見た目を自由に決められ、サイトの CSS や広告の影響を受けない。置き換えが崩れる問題も避けられる |
| 今のタブに重ねる（拡張のページを別に開かない） | 今の翻訳処理をそのまま使え、本文の受け渡しやリンク・画像の扱いが要らない |
| 開いた時点の写しにする | 読んでいる最中に本文が変わったり、位置がずれたり、訳し直したりするのを避ける |
| リーダーを開いている間はリーダーの中だけを訳す | llama-server へのリクエストが 2 倍になり、リーダーの訳が遅れるのを避ける |
| 吹き出しを本文の背景と区別できる色にする（元のページは固定の薄い黄、リーダーは背景ごと） | 白地の吹き出しは、白いページでは本文と同じ色になり目立たなかった |
| `@mozilla/readability` を使う | Firefox のリーダービューで使われている。0.6.0、Apache-2.0、展開後の大きさは約 150KB（2026-11-28 に npm で確認） |

## 未確認・リスク

| 項目 | 影響 | 確認方法 |
| --- | --- | --- |
| Readability が content script の中で問題なく動くか | 抽出の方式が変わる | 最初に、基準ページと react.dev で試す |
| Shadow DOM の中で、今の翻訳処理（`IntersectionObserver`・`MutationObserver`・段落の抽出）がそのまま動くか | 翻訳処理を分ける必要が出る | 同上 |
| 技術記事で、Readability が見出しのアンカー・表・画像を残すか | 本文が欠ける | 基準ページと react.dev で目視する |
| ゴシック・明朝のフォント名が環境ごとに正しく当たるか | 意図しないフォントになる | Mac で確認する。他の OS は代わりのフォントでよしとする |

## 後で決めてよいこと

ショートカットキーの組み合わせ、文字の大きさと行幅の段階数、背景 3 色の色の値、吹き出しを画面の端で上下どちらに出すか。どれも設計の形には影響しない。
