# ブラウザ翻訳拡張（ローカル LLM）基本設計

最終更新: 2026-11-27

## 目的と期待する結果

Chromium 系ブラウザで英語の Web ページ（主に技術記事）を読むとき、Chrome や Safari の翻訳より正確で自然な日本語にする。

Chrome の翻訳で困っていたのは、文中の `code`、リンク、強調で文が崩れることだった。

> 原文: Parse a PDF, chunk it, embed it, and search it locally with `agent.knowledge.search()`.
> Chrome 翻訳: PDFを解析し、チャンク化し、埋め込み、ローカルで検索しますagent.knowledge.search()。

次の状態になれば目的を満たす。

- 文中の要素（`code`・リンク・強調）が、日本語として自然な位置に保たれる。
- `code` の中身や製品名は訳さない。
- 技術用語（LLM、pi など）を、別分野の意味に取り違えない。

確認には、[An Indic Voice Agent with CUGA](https://huggingface.co/blog/ibm-research/an-indic-voice-agent-with-cuga) を基準ページとして使う。

## 範囲

**扱う**
- Chromium 系ブラウザの拡張機能（Manifest V3）
- PLaMo 3 Translate（GGUF）を llama-server で動かすローカル翻訳
- 英語から日本語への翻訳

**扱わない**
- クラウドの API（Claude、OpenAI、Gemini など）
- 汎用のローカル LLM（Qwen など、PFML3 以外の形式で訳すもの）
- ローカルファイルと PDF
- 拡張からの llama-server の起動・管理

## 全体構成

```
llama-server（router モード、利用者が常駐させる）
  └ PLaMo 3 Translate 0.8B / 2B / 8B（GGUF Q4_K_M）
        ▲ PFML3 を /v1/completions に送る。モデルは /v1/models から選ぶ
        │
service worker（拡張の裏方）
  ・PFML3 のプロンプトを組み立て、送信する（並列か直列か）
  ・設定（URL、モデル、送り方、表示方法、用語集）を管理する
        ▲ メッセージでやり取り
        │
content script（タブごと）
  ・段落を抽出し、文中の要素を番号付きタグに置き換える
  ・訳文のタグを検証し、元の要素に戻してページに反映する
  ・翻訳モードの間、追加・変更された要素を監視する
```

## 主要な振る舞い

### 翻訳の開始と範囲
- ツールバーのボタンで、そのタブの翻訳モードを切り替える。オフにすると原文に戻す。
- 見えている段落を先に訳し、そのあと残りを上から順に訳す（`IntersectionObserver`）。
- 翻訳モードの間は、あとから追加・変更された段落も訳す（`MutationObserver`）。
  - 拡張が差し込んだ要素には目印を付け、監視の対象から外す。
  - SPA で URL が変わっても、同じタブにいる間は翻訳モードを続ける。

### 抽出とタグ
- 対象は `p`、`li`、見出しなどの文章の段落。`pre` やコードブロックは送らない。
- 段落内の `a`、`code`、`strong`、`em` などを `<a1>`、`<c1>`、`<b1>` のような番号付きタグに置き換えて送り、返ってきた訳文で元の要素に戻す。
- タグの数と対応が合わないときは、1 回だけ訳し直す。それでも合わなければ原文のまま残し、訳せなかったことを示す小さな目印を付ける。

### PLaMo への送り方
- 1 リクエストで 1 段落を、PFML3 形式で Completions API に送る。
- **既定は並列**：前後の段落の原文と、ページの説明を `context` に入れる。
- **直列も選べる**：直前の段落の原文と訳文を、翻訳履歴として渡す。
- ページの説明は、`<title>` と `meta description` から自動で作る。
- 文体は `form=polite`（です・ます調）を指定する。

### 用語集
- PLaMo の `glossary` 機能を使い、設定画面で「原語 → 訳語」を編集する。既定は空。
- 段落に含まれる用語だけを、語の区切りで照合して送る（`pi` が `api` に当たらないようにする）。
- 用語集は意味を区別せずに当てはめられる。そのため、ページ内で意味が 1 つに決まる語にだけ使う。

### 表示
- 既定は置き換え。マウスを乗せると原文を表示する。
- 段落の下に訳文を差し込む対訳表示も選べる。React などのページで置き換えが崩れるときの逃げ道にもなる。

### 状態とキャッシュ
- 保存するキャッシュは持たない。翻訳モードの間だけ、タブのメモリに原文と訳文を持つ。
- llama-server につながらないときは、その旨を表示する。

## 決定と理由

| 決定 | 理由 |
| --- | --- |
| ローカルだけで動かす | 費用がかからず、ページの内容を外部に送らない |
| PLaMo 3 Translate に絞る | 翻訳専用で、タグの保持・`context`・`glossary`・文体指定に元から対応している。速く、作る量も最小になる |
| llama-server（GGUF）を使う | 今回の Mac では oMLX より速く、付属の Python コード（`trust_remote_code`）を実行する必要がない。router モードで、1 つの URL から複数のモデルを選べる |
| モデルと送り方を設定で選べるようにする | 速さと品質の兼ね合いが、サイズと送り方で大きく変わる |
| 既定は「並列 + 前後の原文」 | 並列は直列より 2〜2.6 倍速い。訳語の統一が弱くなる分は、`context` と用語集で補う |
| 保存するキャッシュは持たない | ローカルで速いので利点が小さく、古い訳が残る問題を避けられる |

## 実験で確認したこと

環境: M1 Pro / 32GB、llama.cpp 1.0.0（build 12359）、oMLX 0.8.3。基準ページの 8 段落を各条件 1〜3 回ずつ。

| モデル（Q4_K_M） | サイズ | 直列 | 並列（8 本同時） | 品質（目視） |
| --- | --- | --- | --- | --- |
| 0.8B | 0.57GB | 2.7 秒 | 1.4 秒 | 細かい誤訳が 2〜3 か所 |
| 2B | 1.81GB | 7.5〜7.8 秒 | 3.0 秒 | 誤りが 1 か所 |
| 8B | 5.28GB | 22.5〜23.9 秒 | 8.9 秒 | 誤りは見つからず |

- タグと `code` は、すべての条件で 8/8 保たれた。
- oMLX（MLX-4bit）は、直列で 1.3〜1.9 倍遅く、並列でも llama-server より遅かった。
- llama.cpp 0.7.0 と 1.0.0 で、速度も訳文も変わらなかった。
- Qwen 3.6 35B-A3B（LM Studio）もタグを保てたが、思考モードを止めないと 127 秒以上かかった。
- 技術の文では、LLM と pi を誤訳しなかった。ページの説明があると、法学修士の意味の LLM まで「LLM」のまま残した。
- 用語集 `pi→pi` を指定すると、円周率の pi まで「pi の値」と訳された。
- Q2_K は、意味が逆になる誤訳があった。
- 量子化は、公式が標準とする Q4_K_M を使う。

## 未確認・リスク

| 項目 | 影響 | 確認方法 |
| --- | --- | --- |
| service worker から `localhost` の llama-server を呼べるか | 通らなければ構成の前提が崩れる。サーバー側は確認済み：llama-server 1.0.0 は `chrome-extension://` の Origin に対し、事前確認（preflight）と POST の両方で `Access-Control-Allow-Origin` を返した（curl で確認）。拡張の `host_permissions` を含めたブラウザ側は未確認 | 最初に、最小の拡張で確かめる |
| React などのページで、置き換えが崩れたり元に戻されたりする | 置き換えを既定にした場合の最大のリスク | 実際のサイトで試す。崩れるページは対訳表示に切り替えてもらう |
| 「並列 + 前後の原文」と直列の、訳語統一の差 | 既定の送り方の妥当性 | 長めの記事で 3 方式を比べる |
| 1〜2 語だけの見出しやメニューの訳 | 誤訳が起きやすい箇所 | 前後の原文を `context` に入れたときの効果を試す |
| 自動で作ったページの説明の効き目 | 用語の取り違えを防ぐ効果が弱まるかもしれない | タイトルと description だけで、LLM と pi の例を試し直す |
| 用語集の語形の違い（複数形・大文字小文字）と「訳さない指定」 | 用語集の使い勝手 | 小さな例で試す |
| メモリ使用量、同時に送る数（4 や 16）の最適値 | 既定値の決め方 | 計測する |
